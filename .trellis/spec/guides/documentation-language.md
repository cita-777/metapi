# Trellis 文档语言约定

## 默认规则

Metapi 中的开发文档和维护说明，以及由 Trellis 管理、生成或注入的内容，除非用户或外部格式明确要求，默认使用简体中文。这里的“文档”包括：

- `docs/**/*.md` 中新增或实际修改的开发文档与维护说明；
- `.trellis/tasks/**` 下的 `prd.md`、`design.md`、`implement.md`、研究记录、备注，以及 `implement.jsonl` / `check.jsonl` 中面向人的 `reason` 文本；
- `.trellis/spec/**`、`.trellis/workflow.md` 和 `.trellis/workspace/**` 中新增或实际修改的内容；
- 项目本地 Trellis skill、agent、command、prompt 和平台 hook 中新增的说明文字。

## 保留原文的内容

中文是自然语言正文的默认语言，但以下内容应保留规范拼写，不要为了翻译而改名：

- 文件路径、命令、环境变量、配置键、JSON/YAML/TOML 字段和枚举值；
- 代码符号、类名、函数名、HTTP 方法、协议名、包名和测试名称；
- 第三方产品、上游 Trellis 文本、标准名称和用户明确要求的原文引用。

首次出现的技术术语可以写成“中文（English）”，后续使用项目中已经约定的名称即可。代码块和命令块必须保持可直接复制执行。

## 各类文件的写法

| 文件 | 语言要求 |
| --- | --- |
| `prd.md` / `design.md` / `implement.md` | 标题、背景、决策、验收标准和执行说明使用中文；技术标识符保持原文 |
| `research/*.md` | 查询范围、发现、证据和局限使用中文；引用的原始标题或 URL 可保留原文 |
| `implement.jsonl` / `check.jsonl` | JSON 结构和 `file` 路径保持机器可读；`reason` 使用中文 |
| `journal-*.md` | 会话摘要、变更、验证和后续步骤使用中文；提交哈希、命令和文件名保持原文 |
| `.trellis/spec/**` | 规范正文使用中文，示例中的代码和协议字段保持原文 |
| `task.json`、配置和 hook 输入输出 | 不改变机器接口；只在允许的描述/注释字段中使用中文 |

## 例外与迁移

1. 用户明确指定语言时，以用户本次要求为准。
2. 外部工具要求固定格式或固定英文字段时，不翻译字段，只翻译可读说明。
3. 已存在的英文历史记录以及 Trellis 上游生成的公共模板不要求批量回译；只有在实际修改该文件时，新增内容才遵循本约定。
4. 不为了语言转换修改产品代码、协议契约、路径或机器可读字段。

## 提交前检查

- [ ] 新增或修改的 Trellis 自然语言内容默认是简体中文。
- [ ] 命令、路径、代码符号和机器字段仍可复制、解析和检索。
- [ ] 英文段落是有意保留的原文、引用、上游模板或用户指定例外，并且不会掩盖中文说明。
